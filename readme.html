README

Blog Writing Agent

A LangGraph agent, built on Claude and Tavily, that researches, plans, writes, edits and tags blog posts. It writes technical posts and analysis pieces, and saves each one as Markdown with front matter.

Overview

Every run follows the same path at the start and end, and picks one of two writing branches in the middle.

classify -> router -> (research) -+- orchestrator -> [worker x N] -> reducer -> grounding -+- tagger -> save
                                  +- planner -> writer -> editor --------------------------+
KindForHow it writes
technicalEngineering, AI, developer tools, tutorialsOutline of 5–9 sections, parallel section writers with code checks, then an Opus grounding check of cited claims
analysisMedia, culture, business, opinionA thesis and 3–6 argument beats, one writer, then an Opus editor that critiques and revises

For the full pipeline, with the model behind each step and the quality checks, see How it works.

Installation

You need Python 3.11 or later, an Anthropic API key, and a Tavily API key.

git clone https://github.com/20161302animesh/blog-writing-agent
cd blog-writing-agent
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -e .
cp .env.example .env

Then open .env and fill in ANTHROPIC_API_KEY and TAVILY_API_KEY.

Install with -e (editable) and run from the project folder. The agent looks for .env next to the package, so a regular pip install . may not find your keys (issue #2).

Settings come from .env or your environment. Only the two API keys are required.

Command line

python -m blog_agent "Will Indian OTT ever have its Ted Lasso moment?" --kind analysis --words 800 -v
FlagWhat it does
--kind auto|technical|analysisWhich branch to use. auto (default) lets a classifier decide.
--words NTarget length for analysis pieces. Technical posts take their length from the outline.
--as-of YYYY-MM-DDDate the research treats as "today". Defaults to today.
--no-saveDon't write the post to the output folder
--no-qaDon't write QA snapshots
--no-groundingSkip the technical grounding check
--checkpoint-db PATHSave progress to a SQLite file so a failed run can be resumed
--resume RUN_IDContinue a failed run. Needs --checkpoint-db.
--jsonPrint the full result as JSON
-vLog each step as it finishes

Python API

from blog_agent import write_blog

result = write_blog(
    "How LangGraph checkpointers work",
    kind="technical",       # "auto" | "technical" | "analysis"
    target_words=None,      # analysis only
    save=True,              # write the post to the output folder
    qa=True,                # write the QA folder
)
print(result.title, result.output_path, result.estimated_cost_usd)

What write_blog() returns

FieldContents
title, descriptionFinal headline, and a one-sentence summary (the thesis, for analysis pieces)
markdownThe post with its H1 title, without front matter
kind, modeBranch used, and research mode (closed_book, hybrid, open_book)
tags5–8 tags
output_path, qa_dirWhere the post and the QA folder were written
evidenceThe sources the post could cite
editor_issuesWhat the editor or grounding check changed, and why
section_issuesTechnical sections still failing their checks after a retry
warningsSteps that failed but didn't stop the run
usage, estimated_cost_usdTokens per model, and an estimated cost
planThe outline or thesis plan, as a dict

Resumable runs

With a checkpoint file, a run that crashes (network error, rate limit) continues where it stopped. Steps that already finished aren't repeated or paid for again.

python -m blog_agent "Your topic" --checkpoint-db runs/checkpoints.sqlite
# ...the run fails and prints its run id...
python -m blog_agent --resume 20261013-172341_your_topic --checkpoint-db runs/checkpoints.sqlite
from blog_agent import write_blog, sqlite_checkpointer

with sqlite_checkpointer("runs/checkpoints.sqlite") as cp:
    result = write_blog("Your topic", checkpointer=cp)
    # after a failure:
    result = write_blog("", checkpointer=cp, resume_run_id=run_id)

For another checkpointer such as Postgres, pass serde=blog_agent.checkpoint.make_serializer() so saved plans and evidence load back correctly.

Tools and Studio

As a tool for another agent

from blog_agent import as_tool

tool = as_tool()        # a LangChain tool named "write_blog_post"
llm_with_tools = llm.bind_tools([tool])

In LangGraph Studio

Run langgraph dev in the project folder (needs langgraph-cli[inmem]). It reads langgraph.json and loads the graph. Start a run with {"topic": "...", "kind": "auto"}.

Outputs

Each run gets an id like 20261013-172341_how_langgraph_checkpointers_work.

FileContents
blog_posts/<run_id>.mdThe post, with front matter: title, date, kind, description, tags
runs/<run_id>/NN_<step>.jsonWhat each step changed, and the full state after it. Parallel writers appear as 05_worker_task01.json, 05_worker_task02.json, …
v1_draft.md, v2_editor_revision.md, v3_final.mdThe draft, the edited version and the final post
diff_1_draft_to_editor.diffEvery sentence the editor or grounding check changed

Tests

pip install -e ".[dev]"
python -m pytest

The 18 tests run both branches end to end with fake models and fake search, so they need no API keys and cost nothing. They also cover the failure paths: search down, editor failing, old news being filtered out, and resuming a crashed run.

Cost

A typical post costs $0.20–0.40 in Claude usage and takes 2–4 minutes. Tavily search is billed separately.

Sample postKindCost
Indian Streamers Remake Because It's Cheap Insurance, Not Because They Lack Ideasanalysis$0.22
LangGraph Send Fan-Out vs. a Plain Loop: How to Choosetechnical$0.33
How LangGraph Checkpointers Work: SQLite vs Postgres, and Resuming a Failed Runtechnical$0.36

To spend less: set BLOG_AGENT_EDITOR_MODEL=claude-sonnet-5-5, or turn off the grounding check with --no-grounding.

Known issues

Open bugs and planned improvements are tracked as GitHub issues. The ones most likely to affect you:

  • A regular (non-editable) install may not find your .env (#2).
  • If the planner repeats a section number, one of those sections is dropped from the post (#1).
  • A resumed run reports only the cost of the part it re-ran (#8).

Credits

This project grew out of the blog-writing-agent exercise by CampusX (Nitish Singh). Its notebooks built the original technical pipeline on OpenAI models: a router, Tavily research, an orchestrator, parallel section writers using LangGraph's Send, and a reducer.

This project ports that pipeline to Claude and extends it with the analysis branch, the editor and grounding checks, and the callable blog_agent package. Thanks to CampusX and Nitish Singh for the idea and the starting point.
