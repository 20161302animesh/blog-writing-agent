Blog Writing Agent

You give it a topic. It researches the web, plans the piece, writes it, has an editor check it against the sources, tags it, and saves a ready-to-publish Markdown post.

Two kinds of post: technical and analysis 2–4 minutes per post About $0.20–0.40 per post

The pipeline

Every post starts and ends the same way. In the middle, the topic goes down one of two writing branches, because a tutorial and an opinion piece need different structures.

What each step does

classify

Reads the request and picks the branch. Skipped when you choose the kind yourself.

Haiku
router

Picks a research mode: closed_book (no research), hybrid (needs current examples) or open_book (recent news). If research is needed, it writes up to 8–10 targeted queries.

Haiku
research

Runs the queries in parallel on Tavily, drops low-value sites (Wikipedia, social media), and keeps up to 20 evidence items. News topics only keep results from the last week.

Haiku
plan

Technical posts get a section outline; analysis pieces get a thesis and argument beats. Every plan points at the evidence it relies on by number.

Sonnet
write

Technical: one writer per section, in parallel. Analysis: one writer for the whole piece. Facts must come from the evidence and are cited inline.

Sonnet
edit

Opus reads the draft next to the original source text. It removes or softens claims the sources don't support and never adds new facts or links.

Opus
tag & save

Adds 5–8 tags, drops generic ones like "ai" or "opinion", and writes the post with its title, date, description and tags.

How it keeps the writing honest

Sources come only from search

Evidence the search didn't return is dropped, so the model can't invent a source.

Claims are checked against the source text

The editor sees what each source actually says, not just a summary of it.

Code is checked

Python examples must parse and code blocks must close. A failing section is rewritten once with the problems spelled out.

Fixes can't add links

A grounding fix that introduces a URL outside the evidence is rejected.

Cut-off answers are caught

A response that hit its token limit or was refused is never passed on as if it were complete.

Failures degrade, not crash

A failed search or edit adds a warning and the run continues. With a checkpoint file, a crashed run resumes where it stopped.

Run it, and what you get

From the terminal

# one-time setup: add ANTHROPIC_API_KEY and TAVILY_API_KEY to .env
pip install -e .
python -m blog_agent "Your topic" --kind auto -v

From Python

from blog_agent import write_blog

result = write_blog("Your topic", kind="analysis",
                    target_words=800)
print(result.output_path, result.tags)

Every run produces

  • blog_posts/<run_id>.md: the post, with front matter
  • runs/<run_id>/NN_<step>.json: what each step changed
  • v1_draft.md → v3_final.md: the draft, the edit, the final
  • diff_1_draft_to_editor.diff: every sentence the editor changed
  • Token usage per model and an estimated cost
